Critical

  1. No CloudTrail / GuardDuty / Security Hub (terraform/)

     No account-level audit trail or threat detection. Compromise forensics would be weak.

  2. Long-lived CI IAM access keys (terraform/persistent/iam_cicd.tf)

     Static gitlab-ci-deployer keys instead of GitLab OIDC short-lived credentials. Leak = standing deploy access until rotation.

  3. SECURITY.md overclaims vs reality

     Docs say ALB is restricted to CloudFront prefix lists. Production still opens ALB to 0.0.0.0/0 on 80/443 (security.tf), while the CloudFront prefix-list data source is unused. Origin IP can be hit directly.

  4. WAF managed rules in count-only mode (waf.tf)

     Bot Control and Common Rule Set use override_action { count {} } — they log, they don’t block. Rate limit is the only real block.

  5. SES bounce handler wired to the wrong DB / SG (terraform/persistent/ses.tf)

     Bounce Lambda uses the test DB password/URL and aws_security_group.gitlab. Suppressions won’t land in prod, and the SG choice looks wrong for that path.

  6. Suppression list never consulted

     SuppressionList is written by Lambda, but email.ts never checks it before SendEmail. You can keep mailing bounced/complained addresses (SES reputation risk).

  High

  7. JWT role/org baked into token; no revocation (auth.ts, rbac.ts, admin.ts)

     Role/org come from JWT claims for ~1h. Demotion/deletion doesn’t invalidate existing tokens. requireRole exists but is unused; routes trust the token.

  8. JWT in localStorage (portal Login/Dashboard/Team/Admin)

     Any XSS steals the session. No httpOnly cookies, no refresh/rotation, logout is only client-side delete.

  9. No password reset / change-password flow

     Invitees get a temp password by email with only a soft “please change it” note — nothing forces rotation.

  10. Public free-scan returns full findings + claim token (scan.ts /api/public/scan)

      Authenticated scans redact for non-premium; public scans return full findingsJson. Abuse + free premium bypass for anonymous callers.

  11. Unauthenticated scan abuse / cost DoS

      Rate limit is in-process Fastify (not shared Redis). Multi-task ECS = limit × tasks. Scanner does outbound HTTP for arbitrary URLs.

  12. SSRF defenses incomplete (TOCTOU / DNS rebinding) (website-scanner.py)

      Host is checked, then requests.get runs; DNS can change between check and connect. No pin-to-resolved-IP. Redirects are re-checked (good), but race remains.

  13. Email enumeration (auth.ts)

      Register returns "Email already registered". Login skips bcrypt when the user is missing → timing side channel.

  14. S3 public access blocks disabled (cloudfront.tf frontend/portal)

      block_public_* = false on static buckets. Policy is OAI-only today, but misconfig risk is high. tfsec flags this.

  15. No CSP / security headers on CloudFront

      Still open from prior audit. Helmet is on the API only; static portal/landing get no CSP/frame/referrer policy from CF.

  16. CORS allows missing Origin (security.ts)

      if (!origin) cb(null, true) — non-browser / some cross-origin cases pass. Also logs every Origin (console.log).

  17. Cookie consent still broken on marketing site (frontend/main.js)

      Accept sets ad_storage / ad_personalization granted but never loads the GA script (G-1J0Z7Q1PCV unused). Cookies lack Secure. Portal banner is separate (localStorage) and also gates nothing unless something calls
  hasAnalyticsConsent().

  18. files.zip (~36MB) at repo root

      Nested patch/archive; shouldn’t live in the working tree (bloat / accidental secret risk).

  ────────────────────────────────────────

  Medium — bugs & logic

  19. Social scan ignores requested platform (scan.ts)

      Non-website scans always send { tiktok_username: targetIdentifier }. Facebook/LINE/etc from the UI don’t map to real credentials/APIs.

  20. scanType not validated

      Any string is stored; only website vs everything-else branching.

  21. Premium “redaction” is cosmetic

      Only description is overwritten; severity, type, evidence, remediation remain. List endpoint mutates objects in memory after fetch (fine) but incomplete redaction.

  22. Failed registration still creates org/user (auth.ts)

      If claim/email fails mid-path, user exists unverified; claim can silently fail if token wrong — no error to client.

  23. Race on scan claim

      Two registrations with the same claim token aren’t uniquely constrained; first write wins, second may create an org with no scan and no clear failure.

  24. DSR dual stack

      Node API persists DSRs; services/dsr remains a stateless stub returning fake IDs/progress. Confusing / dead product surface if still deployed.

  25. Consent API is a stub (consent.ts)

      Accepts writes and returns empty lists — bad for a GDPR product.

  26. No Stripe / billing implementation

      Schema has stripeCustomerId / subscriptionStatus; nothing sets active. Premium is unreachable by real payment.

  27. No Prisma migration history

      Still db push-style ops; schema drift across environments is fragile.

  28. RDS defaults weak for prod module (modules/rds)

      Defaults: deletion_protection = false, skip_final_snapshot = true, backup_retention_period = 1, multi_az = false.

  29. ALB deletion protection off (alb.tf)

      Accidental destroy risk in prod.

  30. Health endpoint leaks version (health.ts)

      Returns APP_VERSION (scanner deliberately doesn’t).

  31. Contact form is fake (main.js handleFormSubmit)

      Logs to console and shows success — no backend.

  32. Maintenance mode false positives

      Any health failure (CORS, blip, client offline) shows “scheduled maintenance” and disables scans.

  33. Dashboard session timer bug

      setTimeout for JWT expiry isn’t cleared on unmount/remount → duplicate alerts / navigation.

  34. Team page only ProtectedRoute

      MEMBERs can open /team; API returns 403 (OK), but UX/route guard incomplete vs admin.

  35. verifyUrl in HTML email not escaped (email.ts)

      Lower risk (env + random token), but inconsistent with escapeHtml on names.

  36. Password charset overly restrictive

      Pattern only allows @$!%*?& as specials — rejects common strong passwords (#, -, etc.).

  37. Scanner hyphenated module loading (main.py)

      importlib on *-scanner.py is fragile and hard to test/typecheck.

  38. Website scanner findings cite wrong GDPR articles

      e.g. “Article 37 (Security)” / “Article 19 (Consent)” — incorrect legal mapping, misleading for customers.

  ────────────────────────────────────────

  Medium — security / infra design

  39. ECS tasks egress 0.0.0.0/0

      Expected for scanners, but widens blast radius if a task is compromised.

  40. GitLab ALB / runner open to internet (gitlab_alb.tf, gitlab_runner.tf)

      Public 80/443 (and runner egress all). Needs strong GitLab auth + hardening assumed.

  41. n8n on shared ALB path (n8n.tf)

      Automation UI on same edge as the product; extra attack surface if exposed by host rules.

  42. IMDS / tag mutability / SNS encryption (tfsec)

      Multiple HIGH findings: mutable ECR tags, topics without CMK, instances without IMDSv2 required, ALB not dropping invalid headers, public ALBs.

  43. Hardcoded ACM ARN in test vars (test/variables.tf)

      Account-specific cert ARN committed — brittle and leaks account ID 700951986348.

  44. SES still forwards to all.datawai@gmail.com (ses.tf)

      Leftover wrong-product inbox for inbound support mail.

  45. Destructive scripts in repo (nuke_account.py, force_cleanup.py, wipe scripts)

      Gated, but high-risk if run against the wrong account/credentials.

  46. Docker Compose binds Postgres/Redis/Vault/MinIO to host (docker-compose.dev.yml)

      Fine for local; dangerous if reused on a shared/cloud host (default passwords).

  47. Rate limits not distributed

      Auth/scan limits are per process — insufficient under horizontal scale.

  48. No org-level audit log

      Admin delete user/org, role changes, DSR status flips — no append-only audit trail for GDPR accountability.

  49. MEMBER can create/update DSRs

      Any org member can file/complete DSRs; may be intended, but no maker-checker / admin-only gate.

  50. Admin org delete is hard cascade

      Instant wipe of users/scans/DSRs with no soft-delete, backup, or confirmation token beyond UI.

  51. Empty stub services (services/consent, services/builder) — README-only.
  52. Docs vs impl: SECURITY.md / architecture docs still overstate CloudFront-only origin, encryption posture, etc.
  53. Architecture doc Aurora vs plain RDS (still open).
  54. rbac.ts dead code while hooks reimplement auth inconsistently (reply.send(err) vs structured 401).

  56. Invite temp password may appear in API response when email fails — intentional escape hatch, but logs/proxies may capture it.
  57. Landing vs portal consent models diverge (cookie domain vs localStorage).
  58. GA ID present but unused — consent claims analytics that don’t load.
  59. files.zip / tfsec_output.txt / gitlab_issues_import.csv / agent scripts clutter the root.
  60. Seed/historical bug scaffolding (scripts/seed_new_repo) can reintroduce old vulns if misused.
  61. No automated API tests visible for auth/RBAC/claim-token/SSRF cases.
  62. Blue/green target groups exist without clear evidence of full cutover automation safety nets.
  63. Personal email in SES recipients (christian.watts@…) — ops coupling / privacy.
